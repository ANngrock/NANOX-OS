# Входная инструкция для Claude Code

Работай по `AGENTS.md`. Актуальная архитектура и порядок реализации находятся в `docs/`, а не в старом корневом `ARCHITECTURE.md` или пересказах предыдущих чатов.

Прочитай последовательно:

1. `docs/START-HERE.md` — историческая исходная постановка M0; прочитать
   для контекста, не исполнять повторно.
2. `docs/STATUS.md` — фактическое состояние и доказательства.
3. `docs/ENVIRONMENT.md` — основной checkout и среда.
4. `docs/adr/0001-platform.md`.
5. `docs/ROADMAP.md` — критерии текущего этапа.
6. `docs/specs/BOOT-M0.md` и `docs/specs/TESTING-REPLAY.md`.

M0 завершён для проверенного QEMU/OVMF-профиля: свой Rust UEFI loader,
ELF-ядро, harness `cargo xtask` и ограниченный record/replay реализованы;
доказательства перечислены в `docs/STATUS.md`. Канонический код — Rust-линия
ветки `codex/m0` (commit `b8913fa`). По указанию пользователя приоритет —
M5: сначала host-проверяемые срезы M5 (`docs/specs/M5-NETWORK.md`), затем
M1–M4 как обязательные зависимости для его завершения; порядок срезов — по
`docs/STATUS.md` и `docs/ROADMAP.md`. Язык, привилегии Core и первая
виртуальная платформа выбраны; повторный архитектурный опрос не нужен.

`origin/main` на момент записи содержит расходящуюся неканоническую
C17/ASM-линию. Не сливать и не переносить её код напрямую; она может служить
только источником идей для тестов.

Команды git, cargo, nix и QEMU запускать внутри WSL в основном checkout
(`docs/ENVIRONMENT.md`). Не отсоединяй устройство по старому номеру `PHYSICALDRIVE2`: эти сведения перенесены из чужого сообщения и не подтверждены.

Сохраняй историю и изменения репозитория. Не начинай новый несвязанный Git-репозиторий.
