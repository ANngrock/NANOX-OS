# R — исследовательские результаты: сводка

сделано, чем доказано, во сколько обошлось, где границы и что не получилось.

записано в его отчёте.

## Затраты

Строки кода (`wc -l`) и машинное время на AMD Ryzen 7 5800H, WSL2:

| компонент | код | проверка | время |
|---|---|---|---|
| NIR: реализации и оптимизатор | 886 строк Rust | 888 строк тестов, 473 строки Python-эталона, 300 КБ фикстур | тесты ~1 с; 25 мутантов ~4 мин |
| Свойства и аттестации | 1 761 строка Rust | 219 строк тестов | 26 с; 28 мутантов ~10 мин |
| Планировщик зависимостей | 236 строк Rust | 288 строк тестов, 459 строк отчёта | тесты ~3 с; отчёт ~15 с; измерение стоимостей крейтов ~2 мин |
| Воспроизводимость | правки зонда и `run.py` | `--repro --runs 3` | ~25 с |
| Сравнение NIR с родным кодом | 495 строк примера | перекрёстная сверка на 4 096 входах × 4 правила | ~40 с |

Проверки NIR (тесты и эталон) в полтора раза больше самой реализации: основная
цена — в проверках, а не в компоненте.

## Отрицательные результаты (собранно)

1. **Собственный ISA и компилятор не оправданы:** NIR в 30–330 раз медленнее
   родного Rust и втрое медленнее таблицы правил; ≤ 5 % ядра даже на миллионе
   решений в секунду. Решение — не делать (ISA-DECISION).
2. **Оптимизатор NIR полезен лишь на правилах с зашитой конфигурацией** (−21 %
   инструкций на одном правиле из четырёх).
3. **Планирование по критическому пути проигрывает порядку объявления в 0,7 %
   графов** (до 10,9 %) и ничего не даёт, когда исполнителей хватает;
   на реальном графе этого проекта выигрыш 0,5 с из 6,6 с. Число строк кода не
   предсказывает время компиляции (r = 0,38).
4. **Свойства не нашли ни одного дефекта в компонентах.** Дефекты нашла только
   мутационная проверка — в самих проверках: четыре пропуска при первом прогоне,
   два настоящих (семейства без ветвлений), один ошибка скрипта, один
   эквивалентный мутант.
5. **Воспроизводимость:** один сценарий из 25 (`m1-preemption`) зависит от
   часов хоста по построению и проверяется по маркерам, не по дайджесту.
6. **NIR: вычислитель B на арифметике с делением в ~5 раз медленнее A** (590
   против 108 нс), на остальных правилах сопоставим — он второе мнение о
   семантике, не боевой путь.

## Общие ограничения

- Всё измерено на одной машине (WSL2, Nix-сборка QEMU 9.2.4, rustc 1.90); на
  настоящем SVM, на другом хосте и в самом ядре NANOX не проверялось.
- Эталоны и модели написаны тем же автором, что и реализации, по одной
  спецификации. Общее неверное прочтение не обнаруживается.
- «Доказательство» здесь — полный перебор ограниченной области, а не
  машинно проверяемый вывод; за границей ничего не утверждается.
- Ничто из R не подключено к ядру: ядра с планировщиком, IPC и драйверами пока нет
  (M2–M8 Codex). Применение к ядру — после них и после измерения на нём.

## Что не сделано внутри R

- Запись и воспроизведение недетерминизма гостя (record/replay) для VMM —
  воспроизводимость обеспечена детерминизмом по построению.
- Независимая реализация эталона третьим лицом.
- Формальное доказательство (SMT/Coq/Lean) чего-либо.
- Измерение планирования на реальном запуске служб и сравнение со
  планировщиком Cargo.
