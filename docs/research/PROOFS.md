# Проверяемые свойства конкретных компонентов и версии доказательств

Статус: результат, 2026-09-30. Критерий R «проверяемые свойства конкретных
компонентов и версии доказательств» выполнен в тех границах, что записаны у
каждого свойства. Это **не** доказательства для всех входов.

## Что это такое

Свойство — утверждение о конкретном компоненте с явной границей: «для всех 8-битных
пар операндов», «для всех последовательностей из не более шести символов над
16-символьным алфавитом». Проверка перебирает **все** случаи внутри границы, а
не выборку; за границей ничего не утверждается. Каждый результат записан как
**аттестация**: свойство, его версия, SHA-256 исходников компонента и
исходников проверки, число случаев, итог, граница. Как только изменится хотя бы
один файл, аттестация устаревает и тест `checked_in_attestations_are_current`
падает, пока проверку не запустят заново.

Инструмент — `crates/proofs` (хост, не часть поставляемой системы):

```
cargo run --release -p proofs -- list
cargo run --release -p proofs -- prove  [--out docs/research/proofs.tsv] [ID...]
cargo run --release -p proofs -- check    # свежесть аттестаций, без перезапуска (секунды)
cargo run --release -p proofs -- verify   # перезапуск всего и сравнение с файлом
```

Аттестации — [proofs.tsv](proofs.tsv). SHA-256 написан в крейте (векторы
FIPS 180-4, границы блоков) и считает по нормализованным концам строк.
**Версия** свойства повышается вручную, когда меняется формулировка или граница;
в этой работе `nir.optimize.small-programs-w8` прошло от версии 1 до 3 (ниже,
почему).

## Что нашли

**Ни одного контрпримера к компонентам**: все девять свойств выполнены с первого
прогона. Слабыми оказались сами проверки, и это нашла мутационная проверка.

Проверки проверены на 28 намеренных дефектах в компонентах (инверсия
тождества оптимизатора, потеря `live[t]` на ветвлении, слияние состояний без
сравнения значений, снятие проверки CRC, `<=` вместо `<` в границе буфера, снятие
изоляции портов и проверки VLAN, снятие проверки зависимостей планировщика и др.).
**Обнаружены 26 из 28.** В первом прогоне (17 дефектов в nanox-ir, svc и qga)
четыре не были обнаружены сразу:

- слияние состояний без сравнения значений и потеря `live[t]` на ветвлении —
  семейства из двух–трёх инструкций не содержали ветвления с общим
  использованием значения (настоящая слабость проверки); добавлены семейства
  `[In,J,Y,Z,Ret]` и `[In,In,J,Y,Ret]` (версия 2, затем 3), после чего оба
  обнаружены;
- `self.len <= N` в буфере кадра: прогон падал с паникой, а скрипт считал
  обнаружением только строки `FAIL` (ошибка скрипта); исправлен, падение и
  превышение времени теперь считаются обнаружением, мутант обнаружен;
- снятие проверки нулевых байтов в записи режима — см. ниже.

Во втором прогоне (11 дефектов в vswitch и dep-sched) не обнаружен один. Два
необнаруженных дефекта **эквивалентны относительно утверждения**, а не
пропущены:

- снятие проверки «байты 6–7 записи режима равны нулю»: отказ всё равно ловит
  CRC; избыточность защиты, свойство «повреждённая запись отвергается» не
  нарушено;
- снятие немедленного завершения задач нулевой стоимости в планировщике —
  ускорение, не меняющее результат.

## Ограничения

- **Граница — это всё утверждение.** Нет утверждений за ней: 64-битный
  NIR, программы длиннее четырёх–пяти инструкций, более трёх претендентов на CPU
  и веса вне сетки, сообщения канала агента длиннее шести байт (и буфер больше 4
  байт), коммутатор с более чем тремя портами и двумя кадрами.
- **Не охвачено свойствами коммутатора:** старение записей и время (один момент
  времени), лимит MAC на порт, вытеснение из таблицы, `emit`. Охвачено тестами
  самого крейта, не этим инструментом.
- **Модели написаны тем же автором по той же спецификации.** Неверное прочтение
  спецификации общее для реализации и модели; независимая модель третьим лицом не
  сделана.
- **Аттестация привязана к исходникам, не к компилятору.** Версия rustc и
  параметры сборки в хеш не входят: ошибка компилятора или другая оптимизация
  формально не делает аттестацию устаревшей. Хешируются только перечисленные файлы
  компонента; изменение зависимости, которой нет в списке, не заметно.
- Проверка — тестирование полного перебора, а не формальное доказательство
  (нет SMT/Coq/Lean и машинно проверяемого вывода). Ошибки в самом переборе
  (границы циклов) возможны; от них защищают мутации и счётчики случаев.
- Результаты получены на одной машине; время — справочное.
