# M5: профиль TCP (`crates/net-tcp`)

Статус: реализован и проверен host-тестами как часть среза M5-3. Это
**ограниченный профиль TCP-клиента** для соединения Core с provider, а не
полная реализация RFC 9293; совместимость с RFC заявляется только для
перечисленного ниже. Интеграция с драйвером, IPv4-стеком и QEMU — после
M1–M4 и `crates/net-stack` ([M5-NETWORK](M5-NETWORK.md)).

## 1. Форма API

`no_std`, без `alloc`, `#![forbid(unsafe_code)]`, из зависимостей только
`net-wire`. Соединение не выполняет ввод-вывод и не читает часы:

- `Connection::connect(config, local, remote, iss, tx_buf, rx_buf)` —
  активное открытие; буферы отправки и приёма даёт вызывающий.
- `on_segment(&TcpSegment, now_ms)` — входящий сегмент, уже разобранный
  `parse_tcp` и направленный этому соединению по IPv4-адресам (демультиплексор
  стека); несовпадение портов игнорируется.
- `poll_transmit(now_ms, out)` — не более одного исходящего сегмента (payload
  IPv4) за вызов; вызывать до `Ok(None)`. `BufferTooSmall` не меняет
  состояние; `out` не короче 24 байт.
- `next_deadline()` — ближайший срок таймеров; `send`, `recv`, `close`,
  `abort`, `state`, `error`.
- `iss` выбирает вызывающий (RFC 6528, генератор на CSPRNG появится с
  криптографией M5); crate его не придумывает.

## 2. Кодек сегмента

Заголовок 20 байт, data offset 5–15 слов (`BadHeaderLength`, `Truncated`),
checksum по pseudo-header IPv4 (`BadChecksum`), порты не 0 (`BadPort`),
SYN вместе с FIN или RST — `BadFlags`. Опции: EOL, NOP, MSS (длина 4,
значение не 0; учитывается только на SYN); прочие опции с корректной
длиной пропускаются, иначе `BadOption`. Биты ECN не сообщаются. URG и
urgent pointer не поддерживаются: данные с URG считаются обычными.

## 3. Состояния

CLOSED, SYN-SENT, ESTABLISHED, FIN-WAIT-1, FIN-WAIT-2, CLOSE-WAIT, CLOSING,
LAST-ACK, TIME-WAIT по RFC 9293 3.3.2. Нет LISTEN и SYN-RECEIVED: пассивное
открытие и одновременное открытие (SYN без ACK в SYN-SENT) не
поддерживаются — такой SYN игнорируется.

- **SYN-SENT:** SYN с опцией MSS. ACK вне (ISS, SND.MAX] — ответ RST с
  SEQ = SEG.ACK; RST с допустимым ACK — `Refused`, иначе игнорируется.
  SYN-ACK: MSS отправки = min(свой, MSS пира или 536).
- **Закрытие:** `close` ставит FIN за данными (ESTABLISHED → FIN-WAIT-1,
  CLOSE-WAIT → LAST-ACK); FIN повторяется, пока не подтверждён, и не
  отправляется повторно после подтверждения. TIME-WAIT длится
  `time_wait_ms` (по умолчанию 60 с) и перезапускается повторным FIN.
  `abort` — RST с SEQ = SND.NXT.

## 4. Приём

- **Допустимость** — таблица RFC 9293 3.10.7.4 с арифметикой по модулю 2³²
  (`seq::lt/le/gt/ge/in_window`, RFC 1982). При нулевом окне сегмент с
  SEQ = RCV.NXT допустим: его ACK, окно и RST обрабатываются, данные не
  буферизуются. Недопустимый сегмент без RST — ACK.
- **RST (RFC 5961 3.2):** сброс только при SEQ = RCV.NXT (`Reset`); RST
  внутри окна — challenge ACK; вне окна — молча отбрасывается.
- **SYN в синхронизированном состоянии (RFC 5961 4.2):** challenge ACK.
  Ограничение частоты challenge ACK не реализовано.
- **ACK:** ACK новых данных двигает SND.UNA и освобождает буфер отправки;
  ACK выше SND.MAX — ответный ACK, сегмент отбрасывается; старый ACK
  игнорируется вместе с окном. Окно пира обновляется по правилу SND.WL1/WL2.
- **Данные:** принимаются только по порядку. Уже полученная часть
  обрезается; сегмент, начинающийся после RCV.NXT, отбрасывается с
  дубликатом ACK — очереди пересборки нет, пир повторит передачу. Данные
  сверх свободного места не принимаются. FIN учитывается, только если все
  данные до него приняты.
- **ACK отправляется на каждый сегмент с данными** (delayed ACK нет).
  Обновление окна после `recv` — когда окно выросло не меньше чем на
  min(MSS, буфер/2) с последнего объявления (SWS avoidance получателя).
  Окно не превышает 65535: window scaling нет.

## 5. Отправка, таймеры и перегрузка

- **Размер сегмента:** min(незаданные данные, MSS отправки,
  min(cwnd, окно пира) − данные в полёте). Алгоритма Нейгла нет.
- **RTO (RFC 6298):** SRTT/RTTVAR в миллисекундах, G = 1 мс,
  RTO = SRTT + max(G, 4·RTTVAR) в пределах [`rto_min_ms`, `rto_max_ms`]
  (по умолчанию 1 с и 60 с, начальное 1 с). Замеряется один сегмент из
  только новых данных; повторно переданные не замеряются (Karn). При
  истечении таймера RTO удваивается до максимума и сохраняется до
  следующего замера.
- **Повтор:** go-back-N — SND.NXT возвращается к SND.UNA. После
  `max_retries` таймаутов подряд — `TimedOut`; счётчик сбрасывается любым
  ACK новых данных.
- **Перегрузка (RFC 5681):** начальное окно min(4·MSS, max(2·MSS, 4380));
  slow start (+min(подтверждённые байты, MSS)) при cwnd < ssthresh, иначе
  congestion avoidance (+max(1, MSS²/cwnd) на ACK). По таймауту
  ssthresh = max(данные в полёте / 2, 2·MSS), cwnd = 1 MSS.
- **Нулевое окно (RFC 9293 3.8.6.1):** пока пир объявляет окно 0, а данные
  ждут, таймер повтора заменяется persist-таймером: проба из одного байта
  с SEQ = SND.UNA, интервал начинается с RTO и удваивается до `rto_max_ms`;
  пробы не входят в `max_retries` и соединение не закрывают.

## 6. Не входит в профиль

Fast retransmit и fast recovery, SACK, window scaling, timestamps (и PAWS),
пассивное и одновременное открытие, urgent data, delayed ACK, Нейгл,
очередь пересборки, ограничение частоты challenge ACK, проверка ACK ниже
SND.UNA − MAX.SND.WND (RFC 5961 5.2), keep-alive, ICMP-сигналы, выбор ISN.

## 7. Проверки

`crates/net-tcp/tests/segment.rs` (7) и `tests/connection.rs` (18):

- кодек: round trip с MSS и без, checksum с pseudo-header, data offset,
  все правила опций, флаги, порты, ECN, нехватка буфера, арифметика с
  переходом через 0, 20 000 случайных входов без panic;
- неверная конфигурация; SYN с MSS и окном; `BufferTooSmall` не теряет SYN;
  рукопожатие и данные через переход 2³²; повторы SYN 0/1/3/7 с и
  `TimedOut`; правила ACK и RST в SYN-SENT (`Refused`);
- сегментация по MSS, cwnd = 4000 и окну пира; slow start и congestion
  avoidance; порядок данных, дубликат ACK, обрезка перекрытия, старые
  данные; нулевое окно приёма и обновление после `recv`;
- таймаут: go-back-N, cwnd = 1 MSS, RTO 100 → 200 → 400, Karn; расчёт RTO
  по RFC 6298 на двух замерах; лимит повторов в ESTABLISHED;
- persist-пробы 12 раз подряд без `TimedOut`, интервалы 200, 400, 800,
  1600 … 60 000, возобновление с SND.UNA + 1;
- RST точный, в окне и вне окна; SYN; ACK выше SND.MAX; сегмент без ACK;
- активное, пассивное и одновременное закрытие, повтор FIN, отсутствие FIN
  после его подтверждения, TIME-WAIT и его перезапуск; `abort`; чужой порт;
- 20 000 случайных сегментов в установленное соединение: без panic,
  инварианты буферов и данных в полёте соблюдены.
